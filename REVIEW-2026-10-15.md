# Flatframe review, 2026-10-15

Scope: the working tree at `D:\Projects\Flatframe` as it is now, including the uncommitted work (mobile UI fixes, mobile SWAP, mod wiring, wiki weapon stats, Lato ammo, auto-aim, gamepad support, abort warning, update prompt). Reviewed by reading the code. No edits, commits or pushes. The game server was not touched.

How it was checked:
- Read the controls (keyboard, gamepad, touch), the player, melee, weapon fire, damage, crit, enemy damage and alert code, the pause and abort flow, the update prompt, and the weapon data chunks.
- Ran the test suite on a copy of the working tree: 291 tests, 290 pass. The one failure (`sound_library.test.js`, "manifest entries resolve") is an artifact of my copy, which did not include the `.ogg` sound files. It is not a code problem.
- Not done: no browser run, no screen check on phone or iPad, no line-by-line check of the wiki numbers. Wiki values were checked only against the existing audit in `wiki-audit/weapons-audit.md`.

Line numbers refer to the files as they are on disk now.

## Ranked findings

### 1. High: a gamepad player who is downed cannot revive by default
- `src/engine/settings.js:20`: `revive` defaults to `-1` (unbound).
- `src/engine/gamepad.js:249-261` (`actionFor`): with X bound only to Reload, X does Reload while downed. The Revive branch needs `revive` to be bound too, so it never runs.
- Self-revive in `src/warframe/player.js:145` reads the `x` key only, which the default pad layout never sends while downed.
- Impact: on the GameSir G8+ a downed player is stuck until bleedout ends.
- Fix: default `revive` to X (2) and let Reload fall back to another button, or make X revive while downed in `actionFor`.

### 2. High: melee target reach is about half the real swing reach
- `src/weapons/melee_weapon.js:59` (`findBestTarget`) uses `this.range * 8`. The swing check at line 108 uses `UNITS_PER_METER` (15). The lunge and auto-swing use the short reach too: `src/warframe/player.js:371`, `:612`, `:628`.
- Result: at 2.5 m, auto-swing and lunge look for targets within 20 units, but the swing hits out to 37.5 units. Enemies you can hit are not auto-targeted and not lunged at.
- Root cause: the `8` came from the stale comment in `src/engine/constants.js:4` ("1 Meter = 8 pixels"). The real value is 15.
- Fix: use `UNITS_PER_METER` in all four places and fix the constants comment.

### 3. High: auto-swing turns the Warframe toward nearby enemies even while shooting
- `src/warframe/player.js:349-361`: when any enemy is in reach, `this.angle` is set to that enemy (line 354). This happens every frame, whether or not you are firing.
- Bullets still go to the cursor (`handleWeapons` passes `mouseWorld` to `fire`). But the sprite and gun art face the enemy, and the next frame's bullet-jump direction uses this angle (`player.js:241-242`, `:256-257`).
- Fix: only snap the facing when a melee input is pressed, or keep a separate facing value for the auto-swing.
- Design question: should melee auto-swing run at all while a ranged weapon is equipped? If yes, keep it. If not, gate it on the melee weapon being equipped.

### 4. Medium-high: held keys repeat their press
- `src/engine/input_handler.js:103-107`: `handleKeyDown` never checks `event.repeat`. Holding a key sets `pressedKeys` again on every OS repeat.
- Every `isKeyPressed` action sees that as a new press: abilities `1`-`4`, Shift jump, `E` melee, `R` reload, `X` interact.
- Some actions guard against this (jump.js says a bullet jump cannot repeat until landing), so the effect varies. Holding `1` may re-cast Slash Dash; this needs a hand test to confirm.
- Fix: `if (event.repeat) return;` in `handleKeyDown`.

### 5. Medium-high: the update prompt pauses mid-mission and goes against the agreed badge rule
- `src/engine/update_prompt.js:46-48` pauses the game (`window.gamePaused = true`) and shows a modal over the fight.
- Project memory says the update notice is a badge on menus and between missions only, never mid-fight. This modal does the opposite. If the badge is replacing this modal, remove it. If not, it needs the same gating.
- Escape: the capture listener (lines 19-23) only calls `preventDefault`. The game's `InputHandler` still records the `escape` key, so Escape can also open the pause menu once the modal closes (`game.js:1010`). Likely, not confirmed by hand.
- Fix: remove or gate the modal, and call `stopImmediatePropagation()` (or stop the key from reaching the game) when the modal takes Escape.

### 6. Medium: no reset when the window loses focus
- `src/engine/input_handler.js:17-21`: there is no `blur` listener. Alt-tab or a focus loss while `W` is held leaves `keys.w` true, so the character keeps walking until the key is pressed and released again.
- Fix: clear `this.keys` on `window` `blur`, and on `visibilitychange`.

### 7. Medium: wall-clock timers keep running through pause
- `src/weapons/melee_weapon.js:92-99`: the combo resets after 5 s of real time, so a pause longer than 5 s resets the combo.
- `melee_weapon.js:55` (perfect parry window), `weapons/weapon.js:138`, `warframe/weapon_switch.js:15-34` (the 200 ms hold) and the `rotationReadyAt`/`outcomeReadyAt` lockouts in `game.js` all use `performance.now()`, not the game clock that pauses.
- Fix: count these down with `dt` like the rest of the game, or reset them on resume.

### 8. Medium: crit chance overflow is not modeled, and the doc says it is
- `src/combat/critical.js:20` caps crit chance at 100%. The wiki's overflow (extra crit tiers above 100%) is dropped.
- `critical.js:45` says `rollCrit` "Handles red crit overflow". It does not. The comment is wrong, and the mechanic is missing.
- Fix: carry `chance - 1` into the crit-tier roll, or correct the comment and log the gap.

### 9. Medium: 800 KB of planet data loads at startup on every device
- `src/engine/visual_effects.js:11` imports `EARTH_LAND_RINGS` from `src/assets/planets/earth_land.js` (about 800 KB) statically. Phones and the iPad parse it before the menu shows.
- Fix: load it lazily with a dynamic `import()` when the star chart opens, or ship it as data.

### 10. Medium: touch controls
- `src/engine/touch_controls.js:56` and `:60`: two buttons are labelled "DASH". One is Jump (`shift`), the other is Slash Dash (`touch-ability-1`). Rename one (for example "JUMP" and "SLASH").
- `touch_controls.js:51`: a separate MELEE button is still there. Project memory says mobile uses one SWAP button (tap switches, hold for melee). Confirm which one is wanted, then remove the other.
- `src/assets/style.css:499`, `:514`, `:567`, `:592`, `:607`: `#touch-controls .tc-buttons` is defined five times across media queries. Consolidate.
- I did not re-check the 2026-10-12 mobile screenshot issues against the new CSS (no browser run).

### 11. Low-medium: one shot per frame caps fire rate at low frame rates
- `src/weapons/weapon.js:118-125`: `fire()` fires at most one shot per call, and the accumulator carries over. At 30 fps a 20 rps weapon fires slower than its stat says. At 60 fps it is close to correct.
- Fix: loop `while (accumulator >= interval)` with a per-frame cap.

### 12. Low: stale comments that describe the wrong behaviour
- `src/engine/gamepad.js:7`: says "RT fires, LB swaps, Start pauses". Actual defaults: RT fires, Y swaps, LB is the ability modifier, Start pauses.
- `src/engine/constants.js:4`: "1 Meter = 8 pixels" (see finding 2).
- `src/engine/input_handler.js:11`: two comments merged onto one line.
- `src/warframe/player.js:53-55`: three overlapping comments about frame stats.
- `src/weapons/weapon.js:145`: the projectile speed `5000` is an unnamed constant.

### 13. Low: code structure
- `src/warframe/player.js:130` reads `this.finisherTimer`, which is only set elsewhere. It is harmless (`undefined > 0` is false) but should be initialised in the constructor.
- `src/warframe/player.js:17` imports `debug/cheats.js`, so the console cheats ship in release builds. The file says this is on purpose. `resetdata` wipes saves with one console command, so consider a flag or a guard.
- `src/weapons/weapon.js:139`: enemy and player gunshots play at fixed volume, with no distance falloff.
- `src/combat/damage_numbers.js`, `src/ui/menus/arsenal.js` (1,433 lines) and `star_chart.js` (1,225 lines) are long. Not a bug, but the next place bugs will hide.

### 14. Low: weapon data
- `src/data/weapons/chunks/primary-rifle.json`: Sobek is in the rifle chunk. The shotgun needs its own chunk (from the existing audit).
- Sobek and Cleaver lack the top-level fields the other entries have. The audit found Sobek's combat stats correct, so this is a schema gap, not a value error.
- Bo (Tenno starting set) is still missing.
- The audit's fixes for Dera, Lato, Skana and Prova are applied in the working tree: Dera fire 11.25, mag 45, reload 1.8; Lato reload 1.0, damage 40, ammo 210 and pickup 40; Skana 120 total; Prova 128 total. Braton and Grakata match their totals.
- Still open from the audit: the intro dates look templated, polarity values look unreliable, and there is no CC BY-SA attribution.

## Checked and fine

- Abort mission: first pick opens the warning with Keep Fighting as default (`src/ui/menus/pause_menu.js:15-20`, `:93-101`). Abort goes to the main menu without rewards (`src/game.js:1161-1165`). Works as the memory describes.
- PC keys: abilities are `1`-`4` and nothing else uses them for weapons. `F` alone switches weapons (`src/warframe/weapon_switch.js`). This matches memory.
- Gamepad defaults: Y swaps, A/X/B/Y with LB are abilities 1-4, LB is the modifier, and there is no Swap Left or Swap Right entry. Matches memory.
- Lato ammo: 210 max reserve, 40 per pickup (`src/data/weapons/chunks/secondary-pistol.json:19-20`).
- Armor formula for the player `armor / (armor + 300)` and shield regen (`player.js:287-296`) match the wiki formulas used in the comments.
- Damage: the combined crit, stealth and headshot maths in `critical.js:76-80` is consistent with its comment.
